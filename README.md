# 🌙 Dream Diary Bot

Telegram-бот для ведения дневника сновидений. Хранит сны в локальной SQLite-базе, изолируя данные по `user_id`.

## Структура проекта

```
dream_diary/
├── main.py           # Точка входа, регистрация хендлеров
├── utils.py          # Вспомогательные функции (_esc, dream_card) и константы
├── db.py             # Слой базы данных (SQLite)
├── ai.py             # ZvenoAI API: nvidia/nemotron-3.5-super-vl
├── map_scheduler.py  # Фоновое автообновление карты снов
├── handlers/         # Обработчики команд и callback'ов
│   ├── __init__.py
│   ├── menu.py       # /start, /help, главное меню
│   ├── add.py        # /add — диалог добавления сна
│   ├── list.py       # /list — список с пагинацией

│   ├── edit.py       # /edit — редактирование
│   ├── map.py        # /map — карта снов
│   └── voice.py      # Голосовой ввод (faster-whisper)
```

## Команды бота

| Команда | Описание |
|---|---|
| `/start` | Главное меню с инлайн‑кнопками |
| `/help` | Подробная справка по всем командам |
| `/add` | Записать новый сон (диалог: название → описание) (кнопка "📥 Добавить") |
| `/list` | Список снов с пагинацией (5 за страницу) (кнопка "📄 Список") |
| `/search <слова>` | Поиск по названию и описанию, до 20 результатов (кнопка "🔍 Поиск") |
| `/map` | Показать последнюю сохранённую карту снов (кнопка "🗺 Карта снов") |
| `/delete <#N или название>` | Удалить сон по номеру (с учётом текущей страницы) или названию (с подтверждением) |
| `/edit <#N или название>` | Редактировать сон: название, описание, дату (кнопка "✏️ Редактировать" при просмотре) |
| `/cancel` | Отменить текущий ввод |

## Кнопки

Бот предлагает **инлайн‑кнопки** в главном меню:

- **🏠 Главная** – вернуть главное меню.
- **📥 Добавить** – начать запись сна.
- **📄 Список** – просмотреть список записей.
- **🔍 Поиск** – ввести запрос для поиска.
- **🗺 Карта снов** – открыть последнюю автоматически обновлённую карту.

Кнопки дублируют текстовые команды, которые остаются резервным способом управления.

После вызова списка появляются кнопки **«Читать N»**, **«Далее ▶»** / **«◀ Назад»** для пагинации, а после просмотра сна — **«✏️ Редактировать»**, **«🗑 Удалить»** и **«◀️ Назад к списку»**.


## Как выглядит запись

Каждый сон содержит:

- **Название** — строка от 1 до 120 символов
- **Описание** — от 1 до 2000 символов
- **Дата** — автоматически (сегодня), можно изменить при редактировании

При попытке сохранить пустой заголовок или описание бот попросит повторить ввод. Превышение лимита длины также блокируется.

## Редактирование

Сон можно отредактировать двумя способами:

1. **Из списка:** Список → Читать N → ✏️ Редактировать → изменить название / описание / дату (или `.` чтобы оставить текущее).
2. **Командой:** `/edit #N` или `/edit <название>`.

Дата принимает форматы: `ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД`. Если отправить `.` — дата остаётся без изменений.

## Обработка ошибок

- Все операции с базой данных обёрнуты в `try/except sqlite3.Error`. При сбое бот логирует ошибку и возвращает пользователю понятное сообщение (сон не сохранён / не найден / удалён).
- Удаление по номеру корректно работает на любой странице списка: бот запоминает текущее смещение (`offset`) и вычисляет индекс в рамках страницы.
- Поиск ограничен 20 результатами; если их ровно 20, пользователь видит подсказку уточнить запрос.

## База данных

Файл `dreams.db` создаётся рядом с `main.py`. Структура таблицы:

```sql
CREATE TABLE dreams (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id     INTEGER NOT NULL,   -- Telegram user ID
    date        TEXT    NOT NULL,   -- YYYY-MM-DD
    title       TEXT    NOT NULL,
    description TEXT    NOT NULL,
    created_at  TEXT    NOT NULL DEFAULT (datetime('now'))
);

CREATE INDEX idx_dreams_user_date ON dreams (user_id, date DESC);

CREATE TABLE dream_maps (
    user_id       INTEGER PRIMARY KEY,
    patterns_json TEXT    NOT NULL,   -- JSON со списком паттернов
    dreams_count  INTEGER NOT NULL,   -- сколько снов вошло в анализ
    period_start  TEXT    NOT NULL,   -- YYYY-MM-DD
    period_end    TEXT    NOT NULL,   -- YYYY-MM-DD
    last_dream_id INTEGER NOT NULL,   -- MAX(id) сна на момент генерации
    generated_at  TEXT    NOT NULL    -- ISO datetime последнего обновления
);
```

Последняя карта снов хранится в `dream_maps` и показывается из кэша — без повторного обращения к модели.

Каждый пользователь видит только свои сны — изоляция по `user_id`.

Для корректного поиска по кириллице используется `str.casefold()` на стороне Python (SQLite `LOWER` не обрабатывает не-ASCII символы).

## Карта снов

Бот автоматически обновляет карту снов раз в 14 дней. Кнопка **«🗺 Карта снов»** и команда `/map` только показывают последнюю сохранённую карту — они не вызывают модель и не тратят токены.

### Как работает

1. Фоновая задача раз в 6 часов проверяет, каким пользователям пора обновить карту. Первая карта создаётся, когда в дневнике накопилось не меньше 10 снов.
2. Карта обновляется не чаще раза в 14 дней и только если после последней успешной генерации появилось **7 и больше новых снов**. Если новых снов меньше, модель не вызывается, старый кэш и уведомления не меняются.
3. Если 14 дней прошло, но новых снов пока меньше 7, обновление произойдёт на ближайшей проверке после появления седьмого сна.
4. Если с последней успешной генерации прошло 14 дней и новых снов достаточно, бот отправляет сны + промпт (`dream_map.md`) + базу знаний (`summary.md`) в ZvenoAI.
5. Используется платная модель `nvidia/nemotron-3.5-super-vl` (контекст до 1 млн токенов).
6. Модель возвращает JSON со списком паттернов. Результат сохраняется в SQLite (`dream_maps`), после чего бот отправляет короткое уведомление с кнопкой **«🗺 Посмотреть карту»**.
7. Если API вернул ошибку, старый кэш сохраняется, уведомление не отправляется, повтор будет на следующей проверке через 6 часов.

### Какие сны попадают в анализ

- Берутся сны за последние **14 календарных дней**, включая сегодня.
- Если за этот период набралось **14 и больше** снов — анализируются все они.
- Если снов **13 и меньше** — бот добавляет самые свежие более ранние сны, пока не наберётся минимум 14.
- Если во всём дневнике меньше 14 снов — анализируются все.
- Порог в **10 снов** считается по всему дневнику, а не по двухнедельному окну. Для обновления нужно **7 новых снов** с момента последней карты; правки старых снов новыми не считаются.

В карте видно дату последнего обновления, период снов, сколько всего снов в дневнике и сколько из них попало в анализ. Если снов стало меньше 10, последняя карта продолжает показываться с пометкой о минимуме.

При первом запуске после обновления кода планировщик через 10 секунд создаст карту, если снов достаточно. Это платный запрос. Первая карта строится при наличии ≥10 снов даже в том случае, если за последние 14 дней записей не было — по правилу добора старых снов.

### Настройка

1. Получить API-ключ в [ZvenoAI](https://zveno.ai/).
2. Добавить в `.env`:
   ```
   ZVENOAI_API_KEY=ваш_ключ
   ```
3. По желанию — наполнить `prompts/summary.md` конспектом по анализу сновидений (используется моделью как база знаний).

> Модель платная: вход — около 19,33 ₽ за 1 млн токенов, выход — около 77,33 ₽ за 1 млн. Одна карта снов на небольшом дневнике стоит примерно 0,3–0,4 ₽. При нулевом балансе или ошибке API карта не обновляется, подробности пишутся в лог.

## Деплой (опционально)

### Systemd (Linux VPS)

```ini
[Unit]
Description=Dream Diary Telegram Bot
After=network.target

[Service]
WorkingDirectory=/opt/dream_diary
Environment=TELEGRAM_BOT_TOKEN=ваш_токен
Environment=ZVENOAI_API_KEY=ваш_ключ
Environment=PROXY_URL=socks5://127.0.0.1:2080
ExecStart=/opt/dream_diary/.venv/bin/python main.py
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
systemctl enable dream-diary-bot
systemctl start dream-diary-bot
```

### Docker

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["python", "main.py"]
```
